# 架构说明

```text
React 工作台 ─┐
模拟闲鱼站 ───┼─> Fastify 本地 API ─> SQLite/WAL
MV3 扩展 ─────┘          │                │
                         ├─> Codex App Server
独立 Worker <────────────┼─> 持久任务队列
                         └─> Action Outbox ─> 浏览器扩展
```

API 只监听 `127.0.0.1`。Codex 只能返回内容、文件和结构化动作提案，不能直接点击闲鱼。外部动作先经过策略引擎，再写入 Outbox；扩展验证页面、DOM 指纹和前置条件后执行。动作结果不明时进入 `RESULT_UNKNOWN`，不自动重试。

## 连接器

- `MockConnector`：阶段 A 的默认连接器，可重复测试完整流程；不访问闲鱼网络。
- `ManagedBrowserConnector`：可见 Chrome/Edge + Manifest V3 扩展，真实联调时启用；所有写动作来自 Outbox。
- `OfficialIsvConnector`：当前为显式不可用实现，调用会失败关闭；未来只有存在经核验的官方合规能力并新增迁移后才能启用。
- 私有协议连接器：注册表不接受未知连接器，明确禁用 Cookie、私有签名接口和逆向 API 回退。

## Codex 会话

- 店铺运营主会话：经营分析、跨商品计划。
- 商品策划会话：一个商品一个持久线程。
- 定制订单会话：当前失败关闭。订单级线程与回合返回 409，不会把订单内容交给 Codex；半定制先走人工流程。

店铺与商品会话默认开放当前项目目录，额外目录通过 Codex 原生权限请求按回合授权。订单能力只有在版本化线程绑定、单订单工作区、旧线程轮换、审批方法白名单和同意撤回复核都通过测试后才可重新启用。

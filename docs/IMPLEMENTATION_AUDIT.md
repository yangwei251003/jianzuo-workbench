## 已加固的审查问题

- MV3 30 秒心跳与过期窗口冲突：统一为 45 秒失败关闭窗口。
- MV3 周期闹钟可能丢失：后台加载和浏览器启动时都会检查并重建 30 秒心跳闹钟。
- API 重启残留“在线”：启动时强制清空旧页面绑定，等待新心跳。
- 账号仅靠昵称：增加可见昵称、公开资料路径和头像路径的本地 SHA-256 指纹。
- 多标签页振荡：扩展优先绑定有账号身份的受控闲鱼标签页；动作按审批时标签页执行。
- 许可证子串绕过：改为严格 SPDX 白名单。
- 审批后动作不派发：审批成功后主动唤醒 ExtensionHub。
- 价格底线和文案价格不一致：要求底价精确为 90%，并核对详情三档价格与商品库。
- 草稿写入假成功：回读标题/详情/价格/图片，校验不通过不推进状态。
- 扩展把“点击成功”误报为业务成功：发布、回复和交付都必须出现本次动作的新结果证据；证据缺失或订单号不一致时，服务端强制记为 `RESULT_UNKNOWN`。
- 最终点击前页面发生变化：扩展会重新读取账号、目标、最新买家消息、输入框和按钮；切换会话或买家追加消息后停止旧动作。
- 长消息预览掩盖风险词：服务端按完整规范化正文哈希核对，超过 20,000 字时直接转人工，不用预览文本做安全判断。
- 客服旧草稿：绑定最新入站消息 ID、正文哈希和决策版本。
- 会话或订单串错防护：目标契约要求当前页面只有唯一可见目标，阶段、目标和当次审批形成三层闸门，并在派发和回执时继续核对；真实卖家订单目标仍须受控实机校准后才能放行。
- AI 任务“完成”但文件无效：候选图必须通过受控目录、PNG 解码、尺寸、大小和 SHA-256 验真后才能替换模板。
- Codex 改写直接污染正式文案：Codex 只能写入隔离 JSON 候选；价格、字段、禁词、事实、文件路径和 SHA-256 全部通过后，仍需用户核对差异并二次确认，才保存为新版本。
- 百度上传误当交付完成：上传后只进入“等待粘贴链接”，不会自动创建个人分享或向闲鱼发送。
- 百度同大小文件被替换：每个上传分片重新读取并校验 MD5，服务端返回的分片 MD5 不一致时停止合并。
- 到期数据仍残留在动作记录：终态 Outbox 到期后只保留审计骨架并脱敏载荷；活动动作引用的数据不会被误删，`RESULT_UNKNOWN` 仍不可重放。
- 指标证据不足：只接受白名单整数指标，并记录账号、DOM 指纹和服务器接收时间。

## 仍需用户手动完成

1. 重新连接扩展，确认当前可见账号指纹仍与已绑定账号一致。
2. 准备一个受控测试买家，不使用首位真实买家做试验。
3. 对一件测试商品批准“只填草稿”，人工核对六图、文案、价格和许可证。
4. 用户再次确认后，只发布这一件测试商品。
5. 打开测试买家会话并采集当前可见目标，生成回复草稿，人工核对后在消息页批准一条低风险 FAQ 回复。
6. 打开受控测试订单；只有真实订单专属适配能够识别唯一订单目标时才采集，否则停止并等待适配更新。采集通过后仍要先走模拟交付，再制作固定数字交付包。
7. 如附件过大，人工批准百度上传；上传后由用户创建并粘贴 HTTPS 分享链接，再批准受控交付。
8. 订单 Codex 在单订单工作区和审批白名单完成前保持禁用，半定制先由人工完成。

真实发布、回复和交付完成受控验收前，不会宣称“除退款外真实全自动运营已完成”。退款永远人工执行。
